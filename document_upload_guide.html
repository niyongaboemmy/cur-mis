📁 Document Upload Storage & Acceptance Guide

✅ Current System Status

The document upload system is fully functional and accepts documents through a dedicated file server.

1. Storage Location

Primary Storage Path:

/file-server/storage/uploads/

Metadata Tracking:

/file-server/storage/uploads/metadata.json

File Structure:

  • Files are stored with UUID-based names
  • Original filename and metadata preserved in metadata.json
  • Each file gets a unique ID (UUID v4)
  • Example: a1b2c3d4-e5f6-7890-abcd-ef1234567890.pdf

2. Accepted File Types

MIME Types Accepted:

File Type MIME Type Extensions Max Size
PDF Documents application/pdf .pdf 5 MB per file
JPEG Images image/jpeg .jpg, .jpeg
PNG Images image/png .png
WebP Images image/webp .webp

3. Allowed File Extensions

System-wide Allowed Extensions:

pdf, jpg, jpeg, png, webp

Faculty-Specific Requirements:

Each faculty can configure which document types are required. The allowed extensions can vary by document type. Check the admission_requirements table for faculty-specific configurations.

⚠️ Important: Additional file-type restrictions are configurable per document type in the database table document_types with the column allowed_extensions

4. Upload Validation Process

When a document is uploaded, the following checks occur:

  1. File Size Validation
    • Maximum: 5 MB per file
    • PHP max upload: 50 MB (configured in file-server/.env)
  2. MIME Type Validation
    • Uses actual file content detection (not client-supplied type)
    • Only 4 MIME types allowed: PDF, JPEG, PNG, WebP
  3. File Extension Validation
    • Checked against requirement-specific allowed_extensions
    • Faculty-based document requirements enforced
  4. Document Type Validation
    • Document type must be required for applicant's faculty
    • International applicants can always upload visa documents

5. Application Status Restrictions

Documents can only be uploaded when application status is one of:

Status Description
draft Initial application - not yet submitted
submitted Application submitted - documents being prepared
documents_under_review Admin is reviewing documents
documents_rejected Can re-upload rejected documents
requested_changes Can re-upload after changes requested

6. Database Storage

Application Documents Table:

student_applications.id application_documents (linked by application_id)

Document Record Fields:

  • id - Document record ID in database
  • application_id - Related application
  • document_type_id - Type of document (e.g., passport, diploma)
  • file_server_id - UUID of file in file-server storage
  • file_original_name - Original filename uploaded
  • file_size - File size in bytes
  • file_mime - MIME type
  • verification_status - pending | verified | rejected
  • verification_comment - Feedback on rejection

7. Troubleshooting Upload Errors

Common Error: "ERROR" in feedback

This typically indicates one of the following issues:

  1. Invalid File Type: Only PDF, JPEG, PNG, WebP are allowed
  2. File Too Large: Maximum 5 MB per file
  3. Wrong Document Type: Document type not required for your faculty
  4. Wrong Application Status: Cannot upload at current stage
  5. File Server Unavailable: Storage service is down

Solutions:

  • Convert file to PDF or JPEG
  • Compress image files to under 5 MB
  • Verify you're uploading the correct document type
  • Wait until next application stage if currently in an upload-restricted status
  • Contact support if file server errors persist

8. API Endpoints

Upload Endpoint:

POST /api/applicant/documents

Parameters:

  • document_type_id - Document type ID (required)
  • document - File upload (required)

Response:

{ "id": 123, "document_type_id": 5, "file_server_id": "uuid-here", "file_original_name": "passport.pdf", "verification_status": "pending" }

9. File Server Configuration

Configuration File:

/file-server/.env

Key Settings:

  • FILE_SERVER_KEY - API key for authentication
  • MAX_UPLOAD_SIZE - 50M (server max)
  • STORAGE_PATH - /file-server/storage/uploads/

10. Security Features

  • ✅ MIME type validation based on file content (not extension)
  • ✅ File size limits enforced (5 MB per file)
  • ✅ UUID-based storage prevents file collisions
  • ✅ Metadata tracking for audit trail
  • ✅ API key authentication for file server
  • ✅ Multi-application access controlled by email verification
  • ✅ Document re-upload support with verification status tracking
