## 3. Build the React frontend

Run this **on your local machine** before uploading.

```bash
cd frontend

# Set the production API URL
# This must point to wherever your backend will live on cPanel
echo "VITE_API_URL=https://api.yourdomain.com" > .env.production

# Build
npm run build
```

The `frontend/dist/` folder now contains the static site. It already includes
`dist/.htaccess` (copied automatically from `frontend/public/.htaccess` by Vite).

## 4. Upload files

### Option A — cPanel File Manager (GUI)

1. Log in to cPanel → **File Manager**
2. Navigate to `public_html/` (or the relevant subdomain directory)

**Backend:**
- Create a folder `public_html/api/` (or use a subdomain — recommended, see step 9)
- Upload the entire `backend/` folder **except** `vendor/` (Composer will generate this on the server)
- Make sure hidden files (`.env.example`, `.htaccess`) are uploaded — File Manager shows hidden files via **Settings → Show Hidden Files**

**Frontend:**
- Upload the **contents** of `frontend/dist/` (not the `dist/` folder itself) to `public_html/` (or your React subdomain root)

### Option B — FTP / SFTP (recommended for large projects)

```bash
# Example using rsync over SSH (fastest)
rsync -avz --exclude='vendor/' --exclude='.env' \
  ./backend/ user@yourdomain.com:~/backend/

rsync -avz \
  ./frontend/dist/ user@yourdomain.com:~/public_html/
```

## 5. Set up the database

1. cPanel → **MySQL Databases**
2. **Create a new database** — e.g. `youracct_cur_mis`
3. **Create a database user** — e.g. `youracct_mis_user` with a strong password
4. **Add user to database** — grant **All Privileges**
5. Note the connection details:
   - Host: `localhost` (or `127.0.0.1`)
   - Database: `youracct_cur_mis`
   - Username: `youracct_mis_user`
   - Password: the password you set

> **Note:** On cPanel, database names and usernames are always prefixed with your cPanel account name (e.g. `myacct_`).

## 6. Configure the backend `.env`

Via cPanel File Manager, create `backend/.env` (copy from `.env.example` and edit):

```dotenv
APP_NAME=CurMis
APP_ENV=production
APP_DEBUG=false
APP_URL=https://api.yourdomain.com
APP_VERSION=1.0.0

DB_HOST=localhost
DB_PORT=3306
DB_DATABASE=youracct_cur_mis
DB_USERNAME=youracct_mis_user
DB_PASSWORD=your_strong_db_password
DB_CHARSET=utf8mb4

JWT_SECRET=generate_a_long_random_string_here_min_32_chars
JWT_EXPIRY=3600

CORS_ALLOWED_ORIGINS=https://yourdomain.com

# Disable API docs in production (or set to true temporarily to verify)
API_DOCS_PUBLIC=false

RATE_LIMIT_MAX=60
RATE_LIMIT_WINDOW=60
```

**Generate a secure JWT_SECRET:**
```bash
# On any machine with PHP:
php -r "echo bin2hex(random_bytes(32));"
# Or on Linux/Mac:
openssl rand -hex 32
```

## 7. Install Composer dependencies

### Via cPanel Terminal (easiest)

1. cPanel → **Terminal**
2. Navigate to the backend directory and install:

```bash
cd ~/backend
composer install --no-dev --optimize-autoloader
```

`--no-dev` omits development-only packages.  
`--optimize-autoloader` generates a classmap for faster autoloading in production.

### Via SSH

```bash
ssh user@yourdomain.com
cd ~/backend
composer install --no-dev --optimize-autoloader
```

> **If Composer is not available:** Download the phar manually:
> ```bash
> php -r "copy('https://getcomposer.org/installer', 'composer-setup.php');"
> php composer-setup.php
> php composer.phar install --no-dev --optimize-autoloader
> rm composer-setup.php
> ```

## 8. Configure PHP version

1. cPanel → **MultiPHP Manager**
2. Find your domain / subdomain for the backend
3. Select **PHP 8.4** from the dropdown
4. Click **Apply**

**Required PHP extensions** (usually enabled by default on cPanel):
- `pdo_mysql` — database connectivity
- `mbstring` — multi-byte string functions
- `curl` — HTTP requests
- `json` — JSON encode/decode
- `openssl` — JWT signing

Verify they are enabled: cPanel → **MultiPHP INI Editor** → select domain → check the extensions list.

## 9. Point domain/subdomain document roots

### Recommended setup (2 subdomains)

| Subdomain | Document Root | Purpose |
|---|---|---|
| `api.yourdomain.com` | `/home/user/backend/public` | PHP REST API |
| `app.yourdomain.com` | `/home/user/public_html/app` | React SPA |

**Create a subdomain:**
1. cPanel → **Subdomains**
2. Subdomain: `api` → Document Root: `backend/public`
3. Repeat for `app` → Document Root: `public_html/app` (upload `dist/` contents here)

### Alternative (single domain, path-based)

If you only have one domain, you can host the React app at `yourdomain.com` and the API at `yourdomain.com/api/` — but this requires more complex `.htaccess` routing. The subdomain approach is cleaner and recommended.

## 10. Verify `.htaccess` files are in place

Two `.htaccess` files are critical:

### `backend/public/.htaccess`

Routes all requests to `index.php`:

```apache
Options -Indexes -MultiViews
RewriteEngine On

RewriteCond %{REQUEST_METHOD} OPTIONS
RewriteRule ^(.*)$ $1 [R=200,L]

RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^ index.php [QSA,L]
```

### React app root `.htaccess` (inside `dist/`, uploaded to SPA root)

Routes all non-file requests to `index.html` for React Router:

```apache
Options -Indexes
RewriteEngine On
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^ index.html [QSA,L]
```

> This file is automatically included in the build (`frontend/public/.htaccess` → `dist/.htaccess`).

**If `mod_rewrite` is not enabled** on your cPanel host, contact support — it is required for both routing systems to work.

## 11. Test the deployment

Run these checks after uploading:

```bash
# 1. Backend health check
curl https://api.yourdomain.com/api/health
# Expected: {"success":true,"message":"API is healthy.","data":{"status":"ok",...}}

# 2. CORS preflight (from a browser-like request)
curl -X OPTIONS https://api.yourdomain.com/api/auth/login \
  -H "Origin: https://app.yourdomain.com" \
  -H "Access-Control-Request-Method: POST" -v
# Expected: 204 No Content with Access-Control-Allow-Origin header

# 3. React SPA — open in browser
# https://app.yourdomain.com  →  login page renders
# https://app.yourdomain.com/nonexistent  →  404 page (React Router, not Apache)

# 4. API docs (if API_DOCS_PUBLIC=true)
# https://api.yourdomain.com/api-docs.php
```

## 12. Security checklist

- [ ] `APP_DEBUG=false` in production `.env`
- [ ] `API_DOCS_PUBLIC=false` in production (or protected behind auth)
- [ ] Strong random `JWT_SECRET` (≥ 32 random bytes)
- [ ] `backend/.env` has `chmod 600` (readable only by the web server user):
  ```bash
  chmod 600 ~/backend/.env
  ```
- [ ] `backend/vendor/` is **not** inside the web-accessible document root (it's in `~/backend/vendor/`, and the document root is `~/backend/public/`)
- [ ] `CORS_ALLOWED_ORIGINS` is set to your exact frontend domain (not `*`) in production
- [ ] All `.htaccess` files include `Options -Indexes` to prevent directory listing
- [ ] Database user has only the privileges it needs (no `GRANT`, `DROP DATABASE`, etc.)
- [ ] SSL/HTTPS enabled for both subdomains (cPanel → **SSL/TLS** → **AutoSSL**)
- [ ] `Retry-After` and `X-RateLimit-*` headers are returned on rate-limited responses

## 13. Updating the app

### Backend update

```bash
# 1. Upload changed PHP files via FTP/rsync
rsync -avz --exclude='vendor/' --exclude='.env' \
  ./backend/ user@yourdomain.com:~/backend/

# 2. If composer.json changed, re-run:
ssh user@yourdomain.com "cd ~/backend && composer install --no-dev --optimize-autoloader"
```

### Frontend update

```bash
# 1. Build locally (set VITE_API_URL if not in .env.production)
cd frontend && npm run build

# 2. Upload dist/ contents to SPA root
rsync -avz ./frontend/dist/ user@yourdomain.com:~/public_html/app/
```

> Vite generates content-hashed asset filenames (`main-AbCd1234.js`), so browser caches are automatically busted on every build. Only `index.html` is served fresh every request (`.htaccess` sets `ExpiresByType text/html "access plus 0 seconds"`).

## 14. Troubleshooting

### 500 Internal Server Error on all API routes

1. Check `APP_DEBUG=true` temporarily and call `/api/health` — the JSON error response will include the stack trace.
2. Look at Apache error logs: cPanel → **Errors** or `~/logs/error_log`.
3. Common causes:
   - Missing `vendor/` directory (run `composer install`)
   - Missing or malformed `.env` file
   - PHP version mismatch (ensure 8.4 is selected in MultiPHP Manager)
   - Missing PHP extensions (`pdo_mysql`, `mbstring`)

### 404 on React routes (page refresh returns Apache 404)

The `.htaccess` inside the React app root is missing or `mod_rewrite` is disabled.

1. Verify `dist/.htaccess` was uploaded to the SPA root directory.
2. Confirm `mod_rewrite` is enabled: add `RewriteEngine On` to `.htaccess`; if Apache throws a 500, the module is not loaded — contact your host.

### CORS errors in browser console

- `CORS_ALLOWED_ORIGINS` in `.env` must exactly match the frontend origin including protocol and port (`https://app.yourdomain.com`, not `https://app.yourdomain.com/`).
- Confirm the `backend/public/.htaccess` OPTIONS rule is present and `CorsMiddleware` runs first in `index.php`.

### "Database connection failed"

- Verify DB credentials in `.env` match the database/user created in cPanel.
- On cPanel, the DB host is almost always `localhost` (not `127.0.0.1`) unless your DB is on a separate server.
- Database name format: `cpanelusername_databasename`.

### Composer not found in cPanel Terminal

```bash
which composer || php -r "copy('https://getcomposer.org/installer', 'cs.php'); include 'cs.php';" && php composer.phar install --no-dev
```

### JWT token expiry issues

- Ensure the server clock is accurate (most cPanel servers sync via NTP).
- Increase `JWT_EXPIRY` in `.env` if users report being logged out too quickly.
- The frontend Axios interceptor auto-redirects to `/login` on 401 responses.
